## 1. 任务执行方式（立即 / 暂不执行 / 定时执行）

### 1.1 需求

1. 创建任务时必须提供「执行方式」三选：**立即执行**（默认）、**暂不执行**、**定时执行**。
2. 立即执行：创建即进入原有启动流程（种子数据 → 目标拆解 → 引擎运行）。
3. 暂不执行：仅创建记录，任务停在 `created` 状态；不占并发额度；用户后续在列表点 ▶ 手动启动。
4. 定时执行：用户给一个未来时间；**由服务端调度循环**到点自动启动（前端不做定时器）。
5. 调度必须满足：
   - 轮询数据库（如 30s tick），**禁止**只用内存定时器——进程重启后排程必须自动续接。
   - **原子认领**：到点任务的「查到期 + 清排程」必须是单条 UPDATE...RETURNING，并发/重复 tick 不得二次启动同一任务。
   - 认领条件：`scheduled_at <= now` 且任务状态为未启动(created) 且未删除。
   - 依赖（LLM 等）未就绪时**不认领**，任务留在排程里等恢复（认领后卡死比不入队更糟）。
   - 到点启动时若内存与 DB 不一致，以 DB 为准并同步内存。
6. 手动启动（start）：未启动任务可随时被手动启动；若存在排程，启动时必须清空排程（提前执行语义）。
7. 任务一经启动（无论到点还是手动），`scheduled_at` 清空；已完成任务不再带排程。

### 1.2 数据模型

```sql
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS scheduled_at TIMESTAMPTZ;
-- 语义：非空 且 status='created' ⇒ 等待到点自动启动。启动即清空该列。
```

任务列表 DTO 必须暴露 `scheduled_at`（RFC3339，未排程为空串）与 `timeout_seconds`、`plan_heartbeat_seconds`。

### 1.3 API 契约

```
POST /api/tasks
  body 增加: run_mode: "immediate"(默认)|"never"|"scheduled"
             scheduled_at: RFC3339（run_mode=scheduled 时必填，必须晚于当前时刻，否则 400）
  行为: immediate→创建即启动；never→仅创建；scheduled→写 scheduled_at，不启动
  响应: 任务 DTO（含 scheduled_at）

POST /api/tasks/{id}/control  {"action": "start"}
  仅 status=='created' 可 start；若带排程先清空；
  启动流程与创建时的启动流程完全一致（种子→目标→引擎）。
  返回: {"id", "status"}
```

### 1.4 验收测试

**自动化（Go test，示例：TestTaskScheduledClaim）**
1. 插入未来排程 → 调用认领函数 → 该任务**不得**被认领。
2. 插入过去排程 → 认领 → 返回该任务 id 且 `scheduled_at` 已清空、status 仍为 created。
3. `SetTaskScheduled(id, nil)` → 排程清空。
4. 认领对同一任务幂等：第二次认领不再返回该 id。

**手工验收**
1. 创建定时任务（2 分钟后）→ 状态「已创建」+ 列表显示「xx:xx 自动启动」→ 到点 30s 内状态变运行中、`scheduled_at` 清空。
2. 重启服务进程 → 排程仍保留 → 到点仍自动启动（关键：排程持久化）。
3. created 任务点 ▶ → 立即启动、排程清除。
4. 停掉 LLM 依赖后到点 → 任务**留在排程里**不启动；依赖恢复后自动启动。

## 2. 任务编辑

### 2.1 需求

1. 创建后可编辑任务定义字段：名称、描述、目标、分类、任务超时（秒）、planner 心跳（秒）、资产覆盖度开关、关联来源任务、执行计划（排程）。
2. **状态边界**（核心，勿放宽）：
   - `description` / `goal` / 关联来源任务：**仅「未启动」与「终态」任务可改**。运行中/已暂停必须 409 拒绝——运行中任务的执行上下文已随首轮规划固化，改任务级字段不影响进行中的执行，只会造成认知不一致；运行中调整目标应走「目标管理」（显式唤醒 planner 重新规划）。
   - 名称/分类/超时/心跳/覆盖度：任意状态可改。
   - `scheduled_at`：仅未启动任务可改；空串=取消排程；RFC3339=设置/改期。
3. 部分更新语义：只更新请求中显式提供的字段（COALESCE 模式）；至少提供一个字段，否则 400。
4. 编辑后**内存态同步**：DTO 与后续规划轮次读到的是新值（不能只写库）。
5. 校验：名称非空≤200 字符；描述/目标非空；分类必须存在；超时≥0；心跳下限归一（如 300s）；排程时间必须晚于当前。
6. **关联企业不可编辑**（创建时确定；企业关联牵动资产归属同步，整体替换风险大）——UI 只读展示。

### 2.2 API 契约

```
PUT /api/tasks/{id}/edit
{
  "name"?, "description"?, "goal"?, "category_id"?,
  "timeout_seconds"?, "plan_heartbeat_seconds"?, "coverage_enabled"?,
  "source_task_ids"?: []string(提供即整体替换),
  "scheduled_at"?: string
}
200 → 任务完整 DTO（编辑后回读）
409 → 状态不允许（含明确原因文案）
400 → 校验失败（含字段级原因）
```

实现要点：DB 用 `UPDATE ... SET 字段=COALESCE($n, 旧值)` 部分更新；更新后必须同步内存任务对象（含生命周期快照）。

### 2.3 验收测试

**自动化（示例：TestTaskEditAndRerunHTTP 的编辑段）**
1. created 任务编辑 name/description/goal/timeout → 200，DTO 回读全部等于新值。
2. created 编辑 `scheduled_at`=未来时间 → 200 且 DTO 回读非空；编辑 `scheduled_at`="" → 200 且回读为空串。
3. created 编辑 `scheduled_at`=过去时间 → 400。
4. 模拟 running 状态后编辑 description → 409；同一状态下编辑 name → 200。
5. 模拟 done 状态后编辑 description → 200。
6. source_task_ids 指向自身 → 400；指向不存在任务 → 400。

**手工验收**：编辑抽屉打开时各字段预填当前值；保存后列表/详情立即显示新值；运行中任务打开编辑抽屉时描述/目标呈灰色不可改并有原因说明。

## 3. 重新进行（rerun）

### 3.1 需求

1. 终态（done/failed/timeout）任务可「重新进行」：复活执行，**保留**图/资产/事实等历史（作为参考），planner 按现状重新规划。
2. **语义核心**：复活前必须把所有已达成(met)目标重置为 open。否则规划器会立即再次判定「目标已全部达成」而秒退——用户看到"点了没反应"。
3. 非终态任务 rerun → 409（未启动任务用 start；运行中任务无需 rerun）。
4. 若并发已满，任务进入 FIFO 队列等待（status 显示排队中），有空位自动晋升。
5. failed/timeout 任务复活时需重置其超时/失败闸门（如超时时钟）。
6. UI：列表行终态显示 ▶（重新进行）；详情页终态显示「重新进行」按钮。

### 3.2 API 契约

```
POST /api/tasks/{id}/rerun
  200 → {"id", "status": "queued"|"running", "queued": bool}
  409 → 非终态 / 正在删除
```

### 3.3 验收测试

**自动化**
1. 终态任务调用 rerun → 200，状态 ∈ {queued, running}。
2. **目标状态断言**：rerun 前该任务 goal 节点 state='met'，rerun 后必须为 'open'（或等价"未达成"态）。
3. created 任务 rerun → 409。
4. 复活后任务不得在无新工作的情况下再次秒退 done（回归重点——本模块初版即因漏掉目标重置而秒退）。

**手工验收**：done 任务点 ⟳ → 状态变运行中 → planner 出现新的规划轮活动（而非立即结束）。

## 4. 前端：任务表单抽屉（创建/编辑双模式）

### 4.1 需求

1. 新建与编辑使用**同一个表单组件**（右侧抽屉），字段/布局/校验完全同构；编辑模式预填当前值。
2. 抽屉受控 open；表单 state 居住在组件内部（打字不触发页面级重渲染）。
3. 编辑模式差异：
   - 预填：全部字段从任务 DTO 初始化（打开时执行，非仅挂载时）。
   - 隐藏创建专属区块：模板、测绘搜资产、文件上传、「首个意图」直投、任务级拦截规则编辑器（提示去详情页拦截规则 tab）。
   - 状态锁：任务运行中/已暂停时，描述/目标/关联任务输入禁用 + 显示原因（改目标请用目标管理）。
   - 关联企业：编辑模式只读展示（含原因）。
   - 执行方式：仅未启动任务显示（可改期/取消排程）。
4. 提交行为：
   - 创建 → POST /tasks；编辑 → PUT /edit；LLM 配置链有 diff 时单独调用链更新接口。
   - 成功后关闭抽屉、刷新列表、按状态给差异化 toast（如"可点 ▶ 启动"/"可点 ⟳ 重新进行"）。
5. 数据自加载：open 时拉取下拉所需列表（分类/企业/任务/LLM 配置），列表页与详情页都能直接挂载。

### 4.2 验收测试（手工）

1. 新建：三选执行方式逐一切换，字段/提示随之变化；定时执行未填时间提交 → 阻止并提示。
2. 编辑：打开预填正确；改字段保存 → 列表刷新显示新值；再次打开确认持久化。
3. 状态锁：运行中任务打开编辑，描述/目标不可编辑；终态任务可编辑并出现"重新进行"提示。
4. 表单输入期间页面其他区域不发生重渲染卡顿（form state 隔离验证）。

## 5. 前端：列表/详情的状态化操作按钮

### 5.1 需求（操作按钮状态矩阵）

| 任务状态 | 行内按钮 | 详情页按钮 |
|---|---|---|
| created | ✏️ 编辑 + ▶ 启动 | ✏️ 编辑（▶ 启动可在列表点） |
| running | ⏸ 暂停 | ⏸ 暂停 |
| paused | ▶ 继续 | ▶ 恢复 |
| done/failed/timeout | ▶ 重新进行 | ⟳ 重新进行 + ✏️ 编辑 |
| queued（排队） | 显示排队态 | — |

1. 列表行按钮**宽度恒定**：不同状态切换按钮而不是增删按钮，避免列跳动。
2. 状态列附加信息：`created` 且带排程的任务，在状态徽章下显示「MM-dd HH:mm 自动启动」小字。
3. 每次操作成功/失败必须有 toast 反馈；失败后刷新列表使按钮回到正确形态。

### 5.2 验收（手工）：逐状态核对按钮矩阵；排队任务显示"排队中"；终态 ▶ 可点且触发重跑。

## 6. 流量页重构（请求重放 / 双栏 / 内联详情 / 拖拽 / 折叠筛选）

### 6.1 需求

1. **请求可编辑**：详情区请求原文（原始 HTTP 报文）可编辑；编辑后标记「已修改」并提供「还原」按钮恢复原文。
2. **重放**：
   - 编辑后的报文可直接重放发送：按编辑内容重建请求（还原 Host/目标），发送至原目标。
   - 不跟随重定向；重放流量不写入流量索引（不留痕）。
   - 支持按已捕获记录 id 一键重放原始报文（无编辑）。
   - 重放结果**替换展示区的 Response**，并提供「原始 / 重放」切换对比。
3. **左右双栏**：详情区 Request 与 Response 左右双栏并排展示（窄屏退化为上下）。
4. **详情内联**：点击列表行，详情面板内联展开在表格下方（非弹窗/抽屉）。
5. **列表高度拖拽**：列表区与详情区之间有可拖拽分隔条，调整高度并记忆。
6. **筛选折叠**：筛选条件收起为一行紧凑布局；「高级筛选」默认折叠（有生效筛选条件时保持展开）；URL/方法等常用筛选直接可用。
7. URL 展示放在重放按钮行（去独立 host 行，紧凑）。

### 6.2 API 契约

```
POST /api/traffic/replay
  {"req": "<编辑后的完整 HTTP 报文>", "scheme": "http|https"}
  或 {"id": <已捕获记录id>}
  行为：解析报文 → 还原目标 → 发送 → 返回响应；不跟随重定向；不写流量索引。
  错误：报文解析失败/目标不可达 → 明确错误信息。
```

### 6.3 验收测试（手工脚本）

1. 选中一条捕获记录 → 编辑请求体某参数 → 点重放 → 展示区出现新响应，可切换「原始/重放」对比。
2. 点「还原」→ 请求区恢复为捕获原文，「已修改」标记消失。
3. 重放一个不存在的主机 → 显示明确错误，页面不崩。
4. 重放产生的流量不出现在流量列表中。
5. 拖拽分隔条 → 高度即时变化；刷新页面后记忆保留（可选）。
6. 高级筛选：默认收起；设置任一高级筛选后收起状态失效（保持展开）；清除筛选后恢复默认收起。
7. 双栏：宽屏 Request 左 / Response 右；窗口缩到窄屏变上下堆叠。

## 7. 多标签导航（keep-alive）

### 7.1 需求

1. 左侧菜单的每个功能页以**标签页**形式打开（含仪表盘、对话等特殊页）；同一页面重复点击不重复开签，而是激活已有签。
2. **keep-alive**：切换标签时页面组件不卸载（如 `display:none` 隐藏而非销毁）——滚动位置、表单内容、轮询定时器在切回后保持。
3. 每个标签可单独关闭（×）；关闭当前签后自动跳转到相邻签。
4. 标签条位于页面 header 的第一行（与版本号/用户区同一栏）。
5. 满幅详情类页面（如任务详情）不进入标签系统，独立全屏路由。
6. 注意：隐藏页面的轮询/SSE 仍在运行——实现时须评估隐藏页的事件处理成本（本条为已知已知，见 §9.5）。

### 7.2 验收（手工）

1. 打开 ≥3 个功能页标签 → 逐个切换 → 各页滚动位置与未提交的表单内容保持。
2. 关闭当前标签 → 自动切到相邻标签；关闭全部 → 回到默认页。
3. 同一菜单重复点击不产生重复标签。

## 9. 实现注意事项（已知坑——复建时对照，均曾实际踩中）

1. **Go map 字面量急切求值**：`map[bool]T{true: ptr.Method(), false: zero}[cond]` 两个 value 都会求值——指针为 nil 时直接 panic。可空指针必须用显式 if/else。（上线后才暴露）
2. **任务可变字段用生命周期快照模式**：加字段时快照读取与写回两个方法都要同步，漏一处即脏读。
3. **部分更新的 SELECT 列清单不含关联展示名**：更新后回读不能直接取扫描结果里的关联名（会拿到空值覆盖内存），需单独补查。
4. **唯一默认配置索引**：插入 `is_default=true` 的 fixture 会撞部分唯一索引；测试绝不触碰用户真实默认配置。
5. **测试污染真实库**：跑集成测试必须使用专用测试库，否则残留 fixture（本库曾残留 20 条垃圾 profile）且可能撑爆磁盘。
6. **datetime-local → RFC3339**：前端 `new Date(v).toISOString()`（按浏览器本地时区解析）；后端解析后必须校验晚于当前时刻。
7. **排队任务的晋升**：从终态/暂停恢复进入 FIFO 的任务，其工作循环可能已退出——晋升条件若要求"引擎例程已注册"会永远跳过它。晋升必须兼容"循环未启动"的任务（晋升动作本身负责启动循环）。
8. **goalless 任务复活**：无 open 目标 + 无活跃意图的复活会立即再次落 done——终态复活前必须重置目标状态（见 §3）。
9. **排程认领的依赖门**：认领前先判依赖就绪，否则任务"既没排程也没运行"两头空。

## 10. 总验收清单（复建完成后逐项打勾）

**自动化（Go test）**
- [ ] TestTaskScheduledClaim：未到期不认领 / 到期原子认领并清列 / SetTaskScheduled(nil) 清除
- [ ] TestTaskEditAndRerunHTTP：
  - [ ] created 编辑全字段 200 + DTO 回读一致
  - [ ] 设置排程→取消→再设置 全程 200 且 scheduled_at 回读正确（曾 panic 路径）
  - [ ] source_task_ids 自引用 400 / 不存在 400
  - [ ] running 编辑 description 409、编辑 name 200
  - [ ] done 编辑 200；done rerun 200（状态 queued|running）；created rerun 409
  - [ ] rerun 后 goal 状态 met→open 断言
